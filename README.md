# 拼团营销系统-用增促活营销服务

## 项目简介

拼团是一种社交裂变营销模式，可有效提升用户粘性和订单转化率。本系统采用微服务架构，将营销中心和交易中心解耦，通过DDD（领域驱动设计）划分边界，实现复杂业务服务解耦与独立拓展。

核心流程涵盖从安全认证、资格核验、营销拼团、支付交易到交易履约的全业务链路，支持活动、标签和交易规则的动态管理，形成用户自传播的私域营销闭环，显著提升营销ROI。

## 系统架构

### 架构特点

- **微服务架构**：营销中心与交易中心独立部署，服务间松耦合
- **DDD设计**：基于领域驱动设计，清晰的业务边界划分
- **高可用性**：支持水平扩展，保障系统稳定性
- **动态配置**：基于DCC实现配置热更新，无需重启服务

### 核心模块

### DDD领域划分

系统采用DDD领域驱动设计，将业务划分为以下核心领域：

- **活动域**：拼团活动配置、活动生命周期管理
- **人群域**：用户标签体系、人群筛选与精准营销
- **交易域**：订单管理、支付流程、交易状态流转
- **鉴权域**：用户认证、权限校验、安全控制
- **商品域**：商品信息、库存管理、价格策略
- **订单域**：订单创建、状态管理、履约跟踪

通过聚合根控制组团状态流转与交易生命周期，并通过领域事件实现跨域协作（如支付完成触发拼团结算），构建完整的拼团交易流程框架。

## 核心业务流程

1. **用户认证**：安全认证机制，保障用户身份合法性
2. **资格核验**：校验用户参与拼团资格，防止刷单作弊
3. **发起拼团**：用户创建拼团活动，生成分享链接
4. **参与拼团**：新用户通过分享链接参团，实现社交裂变
5. **支付交易**：集成支付宝SDK，保障支付安全
6. **拼团成功**：达到成团条件，订单自动确认
7. **交易履约**：订单发货、物流跟踪、售后服务

## 技术亮点

### 1. DDD设计业务框架

系统拆分为拼团和支付两个独立服务，划分活动、人群、交易、鉴权、商品、订单等域。用聚合根控制组团状态流转与交易生命周期，并通过领域事件实现驱动跨域协作（如支付完成触发拼团结算），构建完整的拼团交易流程框架。

**核心价值**：
- 清晰的业务边界，降低模块间耦合
- 领域事件驱动，实现松耦合的跨域协作
- 聚合根统一管理业务状态，保证数据一致性

### 2. 规则树编排和责任链解耦

**规则树编排**：采用组合模式构建试算规则树，串联切量降级、策略优惠与人群过滤等节点，支持活动规则的动态编排。规则树支持灵活配置，运营人员可通过配置中心动态调整规则，无需重启服务。

**责任链模式**：抽象模板承载锁单与结算流程，涵盖活动有效性、库存条件等实时过滤，实现规则与流程低耦合、可插拔。通过责任链模式，可以灵活组合不同的校验节点，满足不同业务场景需求。

**核心价值**：
- 规则与流程解耦，提升系统可维护性
- 支持规则动态编排，快速响应业务变化
- 责任链模式实现流程可插拔，易于扩展

### 3. 无锁化高并发抢占处理

借鉴分段锁思想，对拼团锁单抢占设计无锁化方案。通过CAS（Compare-And-Swap）操作和乐观锁机制，避免传统锁带来的性能瓶颈，支持高并发场景下的库存抢占。

提供恢复量机制确保异常场景下的库存回滚，当订单取消或支付失败时，自动恢复库存，保证库存数据的准确性。

**核心价值**：
- 无锁化设计，大幅提升并发性能
- 支持高并发场景下的库存抢占
- 异常场景自动恢复，保证数据一致性

### 4. 分布式事务最终一致性

营销结算时落地本地消息任务表，异步线程池分发MQ/HTTP回调通知。定时任务+分布式锁实现多实例幂等抢占与失败重试，保证支付成功+拼团结算+业务通知的可靠触达。

**实现方案**：
- 本地消息表：保证消息的可靠存储
- 异步线程池：提升消息发送性能
- 定时任务+分布式锁：保证多实例环境下的幂等性
- 失败重试机制：确保消息最终送达

**核心价值**：
- 保证分布式环境下的数据最终一致性
- 支持多实例部署，避免重复处理
- 失败自动重试，提升系统可靠性

### 5. 高性能人群标签系统

基于Redis BitMap承载海量用户标签，相比传统Set方案压缩空间90%，支持亿级用户实时标签查询。

**技术优势**：
- BitMap存储：每个标签仅占用1bit，大幅节省内存空间
- 位运算查询：支持高效的标签交集、并集、差集操作
- 实时查询：毫秒级响应，支持实时人群筛选

**核心价值**：
- 空间压缩90%，降低存储成本
- 支持亿级用户标签查询
- 毫秒级响应，满足实时营销需求

### 6. 策略模式实现多场景适配

基于策略模式实现多种退单和营销优惠计算业务，适应不同营销场景，满足运营策略配置。

**应用场景**：
- 退单策略：支持不同场景下的退单规则（已支付未成团、已支付已成团等）
- 优惠计算：支持多种优惠策略（满减、折扣、阶梯优惠等）
- 营销规则：支持不同营销活动的规则配置

**核心价值**：
- 策略模式实现业务逻辑解耦
- 易于扩展新的业务场景
- 支持运营灵活配置营销策略

## 系统优势

- **高性能**：Redis缓存 + 数据库读写分离，支持高并发访问；无锁化库存抢占，提升并发性能
- **高可用**：微服务独立部署，单点故障不影响整体服务；分布式事务保证数据最终一致性
- **可扩展**：基于DDD设计，业务模块清晰，易于扩展；规则树编排支持动态配置
- **易维护**：动态配置管理，规则热更新，降低运维成本；责任链模式实现流程可插拔

## 项目结构

系统采用微服务架构，包含两个核心服务：

### 营销中心（group-buy-market）

```
group-buy-market/
├── group-buy-market-api/          # API接口定义
├── group-buy-market-app/          # 应用服务层（启动模块）
├── group-buy-market-domain/       # 领域模型层
├── group-buy-market-infrastructure/ # 基础设施层
├── group-buy-market-trigger/      # 触发器（消息监听）
└── group-buy-market-types/        # 类型定义
```

**核心职责**：
- 拼团活动管理
- 拼团引擎（发起拼团、参与拼团、成团处理）
- 标签管理（用户标签、商品标签）
- 规则引擎（活动规则、营销规则）
- 人群筛选与精准营销

### 交易中心（s-pay-mall-ddd-market）

```
s-pay-mall-ddd-market/
├── s-pay-mall-ddd-api/            # API接口定义
├── s-pay-mall-ddd-app/            # 应用服务层（启动模块）
├── s-pay-mall-ddd-domain/         # 领域模型层
├── s-pay-mall-ddd-infrastructure/ # 基础设施层
├── s-pay-mall-ddd-trigger/        # 触发器（消息监听）
└── s-pay-mall-ddd-types/          # 类型定义
```

**核心职责**：
- 订单管理（订单创建、状态流转）
- 支付服务（支付宝SDK集成）
- 交易履约（发货、物流、售后）
- 退款处理
